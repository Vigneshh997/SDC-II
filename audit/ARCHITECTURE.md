# Implemented X-Fusion architecture

This describes v2 software, not a trained diagnostic model. The release remains blocked by absent genuine paired data.

Exactly three required inputs are image, observed clinical text, and observed structured attributes. Runtime requests carry a de-identified examination ID and an explicit same-examination confirmation. Confirmation is a declaration, not independent proof of matching.

1. **Image:** optional CLAHE (enabled in `config.yaml`), official BiomedCLIP normalization/resize/center crop, pinned authentic BiomedCLIP ViT patch features, two trainable 3×3 CNN layers, and a shared projection. The 196 spatial patches remain a 14×14 map rather than being reconstructed from a pooled vector. Patch adaptation discards the pretrained pooled projection. nnU-Net segmentation from PPT slide 11 is **missing** pending appropriate trained weights and segmentation validation.
2. **Text:** whitespace cleanup preserves negation. The matching pinned CXR-BERT tokenizer supplies padding masks and a maximum 256 tokens. The authentic specialized checkpoint's BERT backbone supplies token embeddings. Its MLM head and sentence projection are intentionally discarded in favor of a trainable shared projection, preserving token-level information. All backbone learned weights load strictly. A historical deterministic `position_ids` buffer is checked against the expected arange before removal for modern Transformers compatibility. No downloaded Python model code is executed.
3. **Metadata:** the default schema uses age and sex because only those observed attributes exist locally. Sex has four explicit categories, encoded as four indicators. Unknown sex is an explicit input, not an inferred default. Age is standardized with training-only mean/std. Additional supported vitals must be explicitly configured and genuinely observed. Missing numeric values fail validation. A trainable two-layer MLP produces a modality token. Normalization buffers are checkpointed.

Default shared dimension is 512 with 8 heads and 2 fusion blocks. The PPT does not specify those numerical values. Each block has three separate `MultiheadAttention` operations. A receiving modality supplies queries, and the other two supply keys and values. Residual connections, layer normalization and feed-forward networks update all three streams. Text padding is masked as context and excluded from pooling. Modality identifiers are learned. The masked pooled streams are averaged before a two-layer classification head. This uses cross-attention operations, not concatenation as a replacement for attention.

Fourteen independent sigmoid outputs follow the verified NIH label ordering in `backend/config.py`. No Finding is an all-zero label vector, not a fifteenth disease. Deployment on a different label schema requires an explicit schema change and new tests; MIMIC labels cannot be renamed blindly into this schema.

The training objective is Asymmetric Loss plus a positive configurable weight times symmetric InfoNCE over all three modality pairs. At least two distinct patients are required in every training batch. The initial loader requires one examination per patient to avoid same-patient false negatives. Incomplete final training batches are dropped. Validation uses all samples. Age/sex alone may yield identical metadata representations for different patients, limiting attainable contrastive separation.

Encoders are frozen by default and remain in evaluation mode during training. CNN refinement, projections, metadata MLP, attention and classifier remain trainable. Configuration can unfreeze encoders, but memory and validity must be reassessed. The GPU verification proves nonzero gradients in each trainable branch and prediction sensitivity to each input on artificial fixtures only.

## Explainability

- LayerCAM uses the positive spatial gradient of a selected class logit, multiplied elementwise by CNN activations and summed over channels. It has no attention-to-saliency substitution. The overlay inverts the official resize/central-crop geometry and preserves original dimensions. Cropped margins have no saliency evidence. This software check does not validate localization against radiologist annotations.
- KernelSHAP explains signed metadata contributions to a selected class probability while image/text are fixed. Its background consists only of recorded training patients. Categorical sex is perturbed as one original field, avoiding invalid one-hot coalitions. No zero-patient background is invented. Correlation and background choice affect the explanation.
- Text attribution uses gradient times the CXR-BERT input embedding for each modeled token, yielding signed local logit sensitivity. It is neither a causal claim nor an exact additive decomposition. Truncation limits modeled evidence to 256 tokens.
- Cross-modal evidence lists high image-patch-to-text attention weights, averaged over heads in the final fusion block. It is explicitly labeled non-causal and not class-specific. Formal cross-modal saliency and SHAP across all input modalities from the PPT diagram are not implemented.

`InferenceService` aggregates actual predictions and available evidence into a JSON report. Each explanation has a method and limitation. Failures are explicitly reported, without replacement evidence. The report includes the provided examination summary, all probabilities/thresholds, selected conditions, image overlay, metadata/text evidence, attention links, model/dataset identifiers and research disclaimer.

## Checkpoints and application

Only explicit v2 checkpoints are accepted. Loading uses `weights_only=True`, strict state compatibility, architecture/label identifiers, training-step counts, dataset/review fingerprints, thresholds and fitted normalization. These checks establish an artifact contract, not independent provenance truth. There is no automatic selection of a legacy checkpoint. The old 1.3 GB checkpoint remains untouched.

FastAPI starts successfully without weights, exposes `/health` and `/schema`, and returns 503 for otherwise valid predictions when no trained model is available. Input errors use 422, unsupported formats 415, oversize files 413, concurrent inference 429 and runtime failures 500/503. A lock prevents overlapping GPU explanation workloads. Requests decode files in memory, validate encoding/MIME/size/dimensions, and never use a supplied filename as a storage path.

The Next.js client reads the backend schema/readiness, requires all observed inputs, previews uploads, displays all scores with checkpoint thresholds, displays methods/statuses and exports the actual JSON report. Unsupported example histories and default vitals were removed. The client has a 180-second timeout; there is no hard backend worker termination deadline. Authentication, distributed scheduling and clinical deployment hardening remain outside the verified local prototype.
